# Remnawave Node Installer

Интерактивный установщик ноды [Remnawave](https://docs.rw) для Debian / Ubuntu. Чистая нода, сайт‑заглушка с SSL, **SelfSteal Reality** с готовым защищённым конфигом для панели (TCP Vision + gRPC), проверка на соответствие правилам хостера, защита порта ноды, управление ядром Xray — всё из одного 3D‑меню со стрелками.

## Запуск

Под root (`sudo -i`):

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/MonopoD123/remnanode-installer/main/install.sh)
```

## Возможности

**Установка**
- **Чистая нода** — Docker, `docker-compose.yml` из панели и запуск, без лишних вопросов.
- **Нода + сайт‑заглушка** — nginx и сертификат Let's Encrypt с автопродлением.
- **SelfSteal Reality** — нода, сайт‑заглушка, сертификат и готовый Config Profile за один проход (5 шагов).

**Конфиг SelfSteal**
- Маскировка только под **свой домен** с собственным сертификатом — без чужих ресурсов, по правилам хостеров.
- **TCP + Vision** и **gRPC** на выбор (по умолчанию оба): gRPC — запасной inbound на своём порту.
- Случайный порт для Hosts при каждой генерации, порты не повторяются.
- Ключи x25519, shortId и `serviceName` для gRPC генерируются автоматически.
- `flow: xtls-rprx-vision` прописан в TCP‑inbound — Remnawave добавляет его в подписку; у gRPC flow явно пустой.
- Усиленный профиль:
  - DoH (1.1.1.1, 8.8.8.8) + запасной системный DNS, если DoH заблокирован;
  - без журнала подключений, только IPv4, `sniffing.routeOnly`;
  - блокировка локальной сети сервера и торрентов;
  - по желанию — блокировка российских сайтов, чтобы RU‑сервисы не видели IP ноды.
- Профиль проверяется ядром Xray самой ноды; если в её geo‑файлах нет списков для России, RU‑правила убираются автоматически.
- Предупреждение, если в домене есть «палевные» слова (`vpn`, `proxy`, `node`, …).
- Сайт открывается по `https://домен` сразу после установки.

**Проверки**
- **Проверить сайт** — DNS, nginx, сертификат, порты Reality, конфликт на 443, доступность DoH, ошибки Xray в логах.
- **Проверка на соответствие SelfSteal** — повторяет проверку хостера: какой сертификат отдаёт каждый порт на чужие SNI.

**Обслуживание**
- **Запуск / остановка / перезапуск ноды.**
- **Ядро Xray** — любая версия из релизов XTLS/Xray-core с проверкой SHA‑256 и откатом на встроенное.
- **Сертификаты для gRPC/TLS** — проброс `/etc/letsencrypt` в контейнер ноды и перезапуск после продления.
- **Защита порта ноды** — API ноды доступен только IP панели; IP определяется автоматически, порт закрывается сам после установки.
- **rkn-guard** — запуск стороннего установщика [Flecksis/rkn-guard](https://github.com/Flecksis/rkn-guard).

**Удобство**
- 3D‑меню: навигация стрелками, быстрый выбор цифрой, статус сервера в шапке; на узких экранах (SSH с телефона) автоматически упрощается.
- Сайты‑заглушки на выбор: «Радио», игра «Курятник», случайный из списка или свой zip по ссылке.
- Проверка email для Let's Encrypt (кириллица и «обрывки» символов не пройдут), понятные ошибки certbot с повтором без email.

## Требования

- Debian 11+ или Ubuntu 20.04+ (нужен `apt`)
- Доступ root
- Для сайта и SelfSteal: домен с A‑записью на IP ноды (в Cloudflare — без проксирования, серое облако) и свободный порт 80 для выпуска сертификата
- Нода, созданная в панели Remnawave (**Nodes → Management → «+»**)

## SelfSteal Reality: как это работает

Reality маскируется под **ваш собственный домен**: nginx с настоящим сертификатом отдаёт сайт‑заглушку на `127.0.0.1:<локальный порт>`, а Xray показывает его всем, кто не является вашим клиентом.

```
клиент ──► :<порт Reality> Xray ──► свой клиент → VLESS
                                └─► чужой / сканер → nginx 127.0.0.1:<локальный порт> → ваш сайт
```

- На **любом** порту и при **любом** SNI сервер отдаёт только сертификат вашего домена — это и есть схема SelfSteal, которую требуют хостеры.
- Если порт Reality **случайный**, nginx дополнительно публикует сайт на 443 — домен работает как обычный сайт.
- Если выбран **443**, его занимает Xray, и сайт открывается через Reality после применения профиля к ноде.

### Установка (пункт 3 → 1)

1. Создайте ноду в панели и скопируйте её `docker-compose.yml` кнопкой **«Copy docker-compose.yml»**.
2. Запустите установщик, выберите **3 → «Установить ноду + SelfSteal»** и пройдите шаги:
   подготовка сервера → нода → порт Reality → сайт и сертификат → запуск ноды.
3. Скрипт выведет готовый Config Profile и настройки хостов, проверит профиль ядром Xray, а когда панель подключится к ноде — сам закроет её порт для остальных.

### Что сделать в панели

1. **Config Profiles** → создать профиль → вставить JSON, выведенный скриптом.
2. **Nodes** → ваша нода → выбрать профиль и отметить его inbound'ы (`VLESS_REALITY_SELFSTEAL_<порт>` и `VLESS_GRPC_REALITY_<порт>`).
3. **Hosts** → создать хост для каждого inbound'а:

   | Поле | Значение |
   |---|---|
   | Inbound | тег из вывода скрипта |
   | Address | ваш домен |
   | Port | порт этого inbound'а |
   | SNI | ваш домен |
   | Fingerprint | `chrome` |

   `serviceName` для gRPC вписывать не нужно — панель берёт его из inbound'а.

4. **Internal Squads** → добавить inbound'ы в сквад пользователей.

Нужен ещё один хост на другом порту — **3 → 2 «Новый конфиг для Hosts»**.

### Что в профиле и зачем

| Настройка | Зачем |
|---|---|
| `target: 127.0.0.1:<порт>`, `serverNames: [ваш домен]` | SelfSteal: маскировка только под свой сайт |
| `settings.flow: xtls-rprx-vision` (TCP) | Без Vision виден «TLS внутри TLS» |
| `settings.flow: ""` (gRPC) | Vision с gRPC не работает — панель не должна его подставлять |
| `log.access: none` | Журнал подключений не пишется |
| `dns`: DoH + `localhost` | Домены резолвятся не через DNS хостера; системный DNS — запасной |
| `UseIPv4` | Без неожиданных выходов по IPv6 |
| `sniffing.routeOnly` | Домен используется только для маршрутизации |
| блок `geoip:private` | Нет доступа к внутренней сети сервера через туннель |
| блок `bittorrent` | Нет жалоб правообладателей хостеру |
| блок `geosite:category-ru` + `geoip:ru` (по желанию) | RU‑сервисы не видят и не собирают IP ноды; в клиенте включите «Россия — напрямую» |

## Где что лежит

| Путь | Содержимое |
|---|---|
| `/opt/remnanode/docker-compose.yml` | Конфиг ноды из панели |
| `/opt/remnanode/docker-compose.override.yml` | Своё ядро Xray и сертификаты (создаётся скриптом) |
| `/opt/remnanode-selfsteal/<порт>-profile.json` | Готовый Config Profile |
| `/opt/remnanode-selfsteal/<порт>-inbound.json` | TCP‑inbound — для добавления в существующий профиль |
| `/opt/remnanode-selfsteal/<порт>-grpc-inbound.json` | gRPC‑inbound |
| `/opt/remnanode-selfsteal/<порт>-host.txt` | Настройки хостов, публичный ключ, shortId, serviceName |
| `/var/www/<домен>/` | Файлы сайта‑заглушки |
| `/etc/nginx/sites-available/<домен>.conf` | Конфиг nginx |
| `/etc/letsencrypt/live/<домен>/` | Сертификат |
| `/var/lib/remnanode/xray` | Своё ядро Xray |
| `/etc/remnanode-guard.conf` | Порт ноды и разрешённые IP панели |
| `/etc/systemd/system/remnanode-guard.service` | Восстановление защиты порта после перезагрузки |
| `/etc/remnanode-installer.conf` | Состояние установщика (домен, порты, выбранные опции) |

## Удаление

Пункт **13** — удалить ноду (контейнер, `/opt/remnanode`, защиту порта, по желанию своё ядро Xray) или сайт‑заглушку (конфиг nginx, файлы, по желанию сертификат и SelfSteal‑конфиги).

## Важно

- Порт ноды (`NODE_PORT`) должен быть открыт **только для IP панели**. После запуска ноды скрипт ждёт подключения панели и сам закрывает порт для остальных; вручную — пункт **11**. Правило касается только этого порта: SSH, сайт и порты Reality не затрагиваются.
- Если на сервере уже включён UFW, скрипт сам открывает в нём порты Reality, 80 и 443; сам UFW скрипт не включает и не настраивает.
- После остановки ноды (пункт 7) она запустится сама при перезагрузке сервера (`restart: always`).
- rkn-guard — сторонний скрипт; запускайте его, только если доверяете автору.
- Скрипт рассчитан на чистый сервер. На сервере с уже настроенным nginx или другими сервисами на портах 80/443 проверьте конфликты перед установкой.
